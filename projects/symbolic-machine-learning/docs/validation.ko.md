## 다운로드 ZIP 재검증과 연결 라이브러리 수정

2026-10-29 새 환경 검증에서 테스트 자체는 통과한 뒤 `PL_cleanup` 종료 중 접근 위반이 간헐적으로 발생했습니다. 아래의 이전 성공 기록은 당시 실행의 결과로 보존하며, 그 기록만으로 간헐적 오류까지 배제할 수는 없었습니다. 네이티브 포인터 검사에서 PySwip이 SWI-Prolog가 계속 참조하는 초기화 인자 배열을 이미 해제한 것을 확인했습니다. 로컬 패키지 **0.3.3+argv1**은 배열과 문자열을 유지하고 끝에 NULL을 추가하며 정상 종료 처리는 그대로 수행합니다. [수정 내용과 원본 출처](../vendor/pyswip/PATCH.ko.md)를 함께 제공합니다.

추가 회귀 검사는 메모리 할당 전후의 실제 네이티브 주소와 Prolog 질의를 확인하고 Python 프로세스의 정상 종료까지 기다립니다. 학습 알고리즘과 평가 데이터, 기존 점수는 그대로 두고 실행 안정성 검사를 추가했습니다. [새 실행 기록](../reports/clean-room-20261029.json)에 ZIP으로 설치한 Windows와 Linux의 검증 범위 및 한계를 기록합니다.

Windows에서 **통합 검증을 5회 반복**했으며 매번 **155개 통과와 권한 관련 2개 건너뜀**을 확인했습니다. Linux에서는 **157개를 생략 없이 통과**했습니다. 각 단계는 종료 코드 0과 빈 표준 오류로 끝났고, 이 실행에 포함된 인자 수명 검사도 독립 프로세스 24개에서 통과했습니다.

## 이전 환경 검증

| 실제 실행 환경 | 런타임 | 확인한 범위 |
| --- | --- | --- |
| 개발 PC의 Windows | Python 3.12.7, SWI-Prolog 9.2.9 x64, 고정 PySwip 0.3.3 | 소스 ZIP 복원과 통합 검증 다섯 단계, 테스트 151개 통과와 2개 건너뜀 |
| 같은 PC의 WSL Ubuntu 24.04, Linux 파일 시스템 | Python 3.12.3, SWI-Prolog 9.0.4, 고정 PySwip 0.3.3 | 소스 ZIP 복원과 통합 검증 다섯 단계, 회귀 검사 153개 및 정상 종료 |
| 오프라인 브라우저 | 실제 Chrome, 영어와 한국어, 데스크톱과 모바일 | 포함한 모델과 입력 변경, 경로 강조 및 논리식 일치 |

Linux에서는 배포후보 ZIP을 Linux 파일 시스템에 풀고 `python tools/run_checks.py --output-dir outputs/verification`를 실행했습니다. **다섯 단계가 25.22초에 완료**했으며 **테스트 153/153개가 생략 없이 통과**하고 프로세스 종료 코드 0과 빈 네이티브 표준 오류를 확인했습니다. 실행 중 소스 해시는 바뀌지 않았습니다. `graph_small` 홀드아웃은 양성 12/12개와 음성 59/59개, 두 초기 트리 학습기는 각각 4/4개를 올바르게 예측했습니다. 별도 순환 그래프의 두 단계 탐색 기본 실행도 양성 12/12개와 음성 12/12개를 올바르게 예측했습니다. 이 값은 명시한 예제의 검증이며 최종 30개 그래프 벤치마크와는 별도입니다.

Windows에서도 같은 소스 ZIP을 풀어 **통합 다섯 단계가 모두 통과**했습니다. 테스트 153개 중 **151개 통과와 2개 건너뜀**, 실패와 오류는 각각 0개입니다. 건너뛴 두 항목은 Windows 권한이 필요한 심볼릭 링크 검사입니다. 두 초기 트리의 기본 실행은 각각 4/4개, 관계 홀드아웃은 71/71개였으며 모든 단계가 종료 코드 0과 빈 표준 오류로 끝났습니다.

[Windows 확인 기록](../reports/verification-windows.json)과 [Linux 확인 기록](../reports/verification-linux.json), [통합 검증 기록](../reports/verification.json)에 실행한 후보 압축 파일과 코드 해시를 남깁니다. 최종 배포본에는 이후 작성한 문서와 증거가 추가돼 후보와 ZIP 해시는 다르지만 검증한 실행 코드의 해시는 같습니다. 포함한 매니페스트로 최종 선언 파일을 확인하며 문서 안에 최종 ZIP 자체의 해시를 넣지는 않습니다.

두 환경은 물리 컴퓨터 한 대를 공유합니다. WSL은 Linux 사용자 공간과 파일 시스템을 분리하며 독립적인 하드웨어나 제3자 컴퓨터의 인증은 아닙니다. Ubuntu CI 설정도 실행 경로를 제공한 것이며 실제 원격 GitHub Actions 완료 없이 통과를 주장하지 않습니다.

## 네이티브 수명 검증

초기 진단에서는 pytest 통과 요약이 출력된 뒤 네이티브 프로세스가 종료하면서 실패한 경우가 있었습니다. 따라서 테스트 요약만으로 실행 성공을 판정하지 않았습니다. 개선 구현은 제한된 질의와 목표 테이블의 수명을 정리하고 임시 절 참조를 Prolog 내부에 한정하며, 학습 예산을 소진한 뒤에도 별도로 정리를 시도합니다. 네이티브 종료를 비활성화해 실패를 숨기지 않습니다.

최종 Windows [수명 반복 보고서](../reports/foil-native-lifecycle.json)는 **새 Python 프로세스 여덟 개**를 기록합니다. 각 프로세스에서 사용하지 않은 재귀 문맥을 닫은 뒤 전체 그래프 학습과 예측 문맥 두 개를 연속 실행했습니다. 모두 종료 코드 0과 빈 표준 오류로 정상 종료했습니다.

최종 두 그래프 탐색 모드는 개선한 소스에서 다시 실행했으며 **벤치마크 프로세스 60개가 모두 종료 코드 0과 빈 표준 오류로 종료**했습니다. [비교 확인 기록](../reports/foil-comparison-validation.json)은 NetworkX의 전이 폐쇄로 정답을 독립 대조하고 두 정책의 입력 및 분할 일치와 공통 완료 조건 20개의 예측 일치를 확인합니다.

기본 pytest는 `setup.cfg`에서 `--capture=sys`를 사용해 Windows의 네이티브 표준 스트림 핸들을 유지합니다. 이 설정과 질의 및 테이블 수명 개선은 별도 조치입니다. 검증은 순차 FOIL 문맥과 격리한 벤치마크 프로세스를 대상으로 하며 동시에 활성화된 문맥의 상호 격리를 보장하지 않습니다.

## 인터랙티브 설명 검증

오프라인 데모는 [`examples/explanation.json`](../examples/explanation.json)을 포함하고 내보낸 트리와 논리식 조건으로 예측합니다. 정답 개념을 별도 판정식으로 하드코딩하지 않습니다.

실제 Chrome에서 영어와 한국어 페이지를 데스크톱 1440×1000과 모바일 390×844로 실행했습니다. 각 조합에서 표의 여덟 행과 체크박스의 여덟 입력을 확인한 **입력 전환 64회** 모두 트리 예측과 논리식, 저장된 경로 및 강조 경로가 일치했습니다. JavaScript 오류와 외부 자산 의존성, 본문의 가로 넘침은 없었습니다. 서버 없이 `file://`로 열어 확인했습니다.

이 데모는 진리표 전체 여덟 입력으로 학습한 모델을 설명하며 미관측 데이터 성능 결과가 아닙니다. 별도의 홀드아웃 측정은 [개선 결과](results.ko.md)에 정리했습니다.

## 초기 자료와 배포 보존

초기 코드와 데이터 및 문서 27개는 고정한 스냅샷에, 초기 PDF 세 개는 `references/`에 바이트 단위로 그대로 남깁니다. 출처 파일은 초기 전체 30개 목록을 제공합니다. 배포 생성기는 초기 해시와 대조하고 초기 DTL 소스의 보존 구간 및 과거 실험 보고서의 일치도 확인합니다.

프로젝트 매니페스트는 검증 도구와 소스, 지원 예제, 문서와 보고서, 그림과 데모 및 초기 근거를 포함합니다. 검증 도구는 체크아웃 또는 다운로드 저장소 ZIP에서 선언한 경로와 크기, SHA-256 및 초기 ZIP 무결성을 확인합니다. 같은 저장소의 다른 프로젝트는 보존하지만 별도 런타임은 이 검증의 범위가 아닙니다.
